title: How to work with Herdr
description: Run Herdr locally, inside SSH, or through remote attach.

Run Herdr where the work lives. Attach from wherever you are.

Herdr is a background session server plus one or more terminal clients. Panes keep running in the server. Clients attach, detach, and render the session.

## Local work

Start Herdr from the project directory:

```bash
herdr
```

Herdr starts or attaches to your local background session automatically. You do not manage sockets. Run shells, servers, tests, and agents normally inside panes.

Detach the client with `ctrl+b q`. Your panes keep running.

Reattach later:

```bash
herdr
```

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Agent labels and reported models

Default Agents rows prioritize each tab's actual label and its last reported
selected session model. An unnamed tab retains its real label/number. Agent kind
and space remain secondary context. Missing model metadata is omitted, not guessed;
custom rows, grouping, and agent-view filters keep their configured behavior.
Model metadata must include a matching `model_agent` owner (the detected CLI kind),
so a previous Pi/Claude model is not shown on another CLI later using that pane.
Old or ownerless model tokens are omitted; other custom tokens are unchanged.
The current snapshot has no session identity to compare, so this is a kind-owner
guard, not proof of an individual inference or process generation.

The Pi integration reports the selected model on session start and model changes.
Claude reports the model supplied by SessionStart, clearing a previous value when
that authoritative event omits it. This version does not install newer Claude
PostModelSwitch hooks: later `/model` switches may not update the label until a
new SessionStart report. Neither integration claims to expose every physical
backend dispatch, and neither reads settings or transcripts to guess it. Existing
installed integration assets need the normal integration update to use this data;
changing this checkout does not modify user hooks or configuration.

## Withdrawn custom presentation and automatic Tasks entry

This custom build keeps the left **Spaces / Agents** sidebar, its layout, custom
rows, filters/grouping, names, tab visibility and reported selected-model labels.
The right Files / Git / PDF / image / Tasks inspector and fullscreen Kanban have
been withdrawn. They have no menu, key, mouse or file-link entry, reserve no
terminal space, and perform no background reads or previews. Standard terminal
selection, URL and supported OSC 8 link activation remain available.

Fresh Pi integrations retain state/session/model reporting but register no Tasks
tools or Tasks prompt section, including in headless hosts. Fresh Claude
SessionStart hooks retain session/model reporting without adapter discovery or
Tasks guidance. Integration versions remain Pi 10 and Claude 12.

The Tasks service, saved data, handoff drain, JSON API, direct CLI and bounded
adapter remain available for **explicit compatibility use**; they are not blocked
or erased. See the [Tasks reference](https://github.com/herdrdev/herdr/blob/master/docs/next/api/tasks.md).
Reports and verification are claims, not Herdr checks. Nothing automatically
starts old todos, claims workers or marks done/pass.

Replacing source or installed assets cannot revoke tools already loaded in an
existing Pi host or remove guidance already sent to Claude. Existing sessions may
retain those until natural reload; this withdrawal does not restart or prompt
agents, rewrite user settings or remove data.

## Remote work through normal SSH

SSH to the machine that has the code and credentials, then run Herdr there:

```bash
ssh you@server
herdr
```

This works like a terminal multiplexer. Your shell is remote. The Herdr server is remote. The agents and panes run on the remote machine. Detach with `ctrl+b q`, disconnect, then SSH back and run `herdr` again.

Use this path when you already live inside an SSH shell, when you are on a phone or tablet SSH client, or when you want the simplest setup.

## Work from your phone

Herdr works on your phone without a mobile app or web dashboard. Install any SSH client, connect to the machine where your agents run, and start Herdr there:

```bash
ssh you@server
herdr
```

The same persistent Herdr session opens in your phone terminal. The TUI adapts to narrow screens, so you can inspect agents, switch workspaces, and check panes without leaving SSH.

On iPhone, apps like [moshi](https://getmoshi.app/) work well.

## Remote work from your local terminal

Attach through SSH without opening a shell first:

```bash
herdr --remote workbox
herdr --remote ssh://you@server:2222
```

The remote server keeps the panes running and sends their terminal content and session state over SSH. Your local Herdr draws the UI using your local theme and presentation settings.

Use this path when you want the remote session to feel local. The client runs on your machine, so local desktop features such as image clipboard paste can be bridged to the remote server. If you SSH first and run `herdr` on the server, Herdr runs entirely on that server and cannot read your local desktop clipboard.

For repeat targets, put the host in your SSH config:

```text
Host workbox
  HostName server.example.com
  User you
  Port 2222
```

Then attach with:

```bash
herdr --remote workbox
```

## Which path to use

Use `herdr` for local work. Use `ssh you@server` then `herdr` when you want Herdr to behave like tmux on that remote shell or when you are using a phone SSH client. Use `herdr --remote <host>` for a local UI attached to one remote session, including local clipboard image paste. To keep Local and several SSH machines in one window, save them with `herdr machine add <host> --label <label>`; see [Connecting machines](/docs/connecting-machines/).

For remote bootstrap details, named remote sessions, custom binaries, and direct terminal attach, see [Persistence and remote access](/docs/persistence-remote/).
